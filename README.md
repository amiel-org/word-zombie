# 单词大战僵尸

面向高中英语词汇训练的跨设备 PWA 游戏。玩家可以点击英文单词装填后射击对应中文词牌，也可以直接把英文拖到僵尸词牌上，在三车道持续来袭的压力下完成中英匹配。

## 当前词库

高中游戏词库只使用《蝶变英语高、中、低频词分类表》：

| 词频 | 数量 | 说明 |
|---|---:|---|
| 高频 | 660 | 优先夯实高考常见词 |
| 中频 | 1,320 | 中频核心 660 + 中频提升 660 |
| 低频 | 1,200 | 拓展识别范围 |
| 合计 | 3,180 | 英文词条去重后仍为 3,180 |

- 人教版旧教材词、短语和固定 20 词关卡已从当前项目移除，不参与游戏或统计。
- 初中入口保留，但词库尚未导入，因此不能开局。
- 每局从所选词频中动态编排 20 个不同单词，不再反复固定出现同一组词。

## 学习规则

- 新档案首局从 20 个未接触词开始。
- 有学习记录后，每局最多先安排 12 个待复习/到期词，其余位置优先使用未接触词；未接触词不足时才使用非到期巩固词和已掌握抽查词。
- 没有到期词时，下一局直接使用 20 个未接触词，避免刚练过的词立即重复出现。
- 同一局尽量避免出现相同中文释义。
- 本局首答正确至少 `14/20`，且防线生命大于 0，才算本关过关。
- “本局首答正确”只代表本局表现，不直接写成“已掌握”。

长期掌握采用间隔复习：

1. 首次首答正确：初步识别，3 天后复习。
2. 到期后再次首答正确：强化中，14 天后复习。
3. 到期后再次首答正确：稳定，45 天后复习。
4. 到期后再次首答正确：已掌握，90 天后抽查。

提前练习可以计入正确率，但不会提前推进掌握阶段。几天不玩不会扣分或降级，到期词会等到下次打开。错配或漏答会降一级、立即进入待复习队列。

完整规则见 `docs/game_rules_v2.md`。

## 游戏体验

- 战场：3 条车道，最多 6 只僵尸并发，三波逐步加速。
- 地图：文化遗产草坪、秋日图书馆、盛夏运动场、雨后实验楼、冬日校园广场、春日书院、海滨校园、屋顶温室共 8 张；每个档案按开局次数独立循环。
- 操作：支持鼠标、触摸、点击和 Pointer Events 拖拽；按黄色单词弹和词牌的矩形重叠判定命中。
- 错配：僵尸立即冲锋且不可再次射击；冲线统一扣 15 HP。
- 纠错：关卡中不中断；本关结束后逐词显示英文、中文和发音，全部确认后再结算。
- 角色：11 种校园僵尸，每局受约束编排 8 种，身体动作与稳定词牌分离。
- 武器：M4A1、AK-47、MP5 和随机武器；武器只改变视觉，不改变学习难度。
- 声音：本地 `Faster` 背景音乐，音乐、音效和发音可分别开关；关后回顾自动暂停背景音乐。

## 学习档案与数据

- 首次打开自动创建“孩子”档案。
- 同一台设备可以新建多个学习档案，各档案进度完全隔离。
- 当前版本不提供访客模式，每次开局都必须选择一个学习档案并保存结果，防止试玩数据来源不明。
- 可以删除不再使用的档案及其全部记录，但最后一个档案不能删除；“清空当前档案”只清除进度，不删除档案本身。
- 浏览器无法打开 IndexedDB 时会禁止开局并明确提示，不会静默进入无保存游戏。
- 学习进度按 `来源网址 + 浏览器 + 设备` 保存在 IndexedDB `word-zombie-learning-v2` 中。
- 同一网址、同一浏览器刷新或关闭后再打开，记录仍会保留。
- 不同 iPad、安卓或电脑的本地数据天然分开；当前版本没有账号和云同步。
- “学习进度”中可以导出全部本地档案为 JSON，也可以在另一台设备导入恢复。
- 浏览器清站点数据、无痕模式或更换部署域名会产生新的本地存储空间，因此应定期导出备份。

看板按高频、中频、低频分别显示总词数、已接触、学习中、稳定、已掌握、到期复习、首答正确率和近期薄弱词。

## 跨设备使用

| 设备 | 推荐浏览器 | 使用方式 |
|---|---|---|
| iPad | Safari | 打开 HTTPS 地址，通过“分享 > 添加到主屏幕”安装 |
| 安卓手机/平板 | Chrome | 打开 HTTPS 地址，使用浏览器“安装应用” |
| Windows/macOS | Chrome 或 Edge | 直接使用，或通过地址栏安装按钮安装 |

- 首次联网访问后，PWA 缓存静态资源，后续可以离线启动。
- iPad Safari、安卓 Chrome、Windows Chrome/Edge 使用设备系统动态 TTS，可直接覆盖 3,180 词。
- 国行安卓若没有英文 TTS，需要在系统文字转语音设置中安装英语语音数据；网页无法静默安装系统组件。
- 正式 PWA 需要 HTTPS。Cloudflare Pages 上传后，应继续使用同一个项目域名，避免本地进度分散到不同来源。

## 本地运行与验证

```powershell
pnpm install
pnpm dev
pnpm test
pnpm build
pnpm test:e2e
```

- `pnpm test`：验证 3,180 词导入、间隔掌握、动态选词、战斗、晋级、声音和存储输入规则。
- `pnpm build`：执行 TypeScript 检查并生成生产版 PWA。
- `pnpm test:e2e`：验证桌面 Chromium、iPad 横屏 WebKit、安卓竖屏和安卓横屏。

重新导入词表：

```powershell
pnpm import:frequency -- "C:\path\to\蝶变英语高、中、低频词分类表(1).xlsx"
```

导入器会生成：

- `data/senior_frequency_words.json`：运行时 3,180 词。
- `data/senior_frequency_audit.json`：分 Sheet 数量、唯一性、必填字段和源文件 SHA256 审计。

## 发布与打包

```powershell
pnpm package:pwa
pnpm package:windows
```

- PWA：`releases/word-zombie-pwa-v2.1.0/`，上传到 HTTPS 静态站点。
- Windows：`releases/word-zombie-windows-v2.1.0/Word-Zombie-Windows-x64.exe`，双击后在默认浏览器本地运行。
- 可传输 ZIP、交付说明和 SHA256 位于 `releases/`。

## GitHub、Cloudflare 与版本发布

- `main` 是生产分支。推送到 `main` 后，Cloudflare Pages 会自动构建 `dist/` 并部署网页版本。
- 版本号以 `package.json` 为准。推送形如 `v2.1.0` 的标签后，GitHub Actions 会在 Windows 环境执行测试、构建 PWA 和 Windows 单文件版，并将两个 ZIP 与 SHA256 校验值发布到对应 GitHub Release。
- 日常网页更新只需提交并推送 `main`；需要发布新的 Windows 安装包时，先更新 `package.json` 中的版本号，再提交、打标签并推送标签：

```powershell
pnpm version 2.2.0 --no-git-tag-version
git add .
git commit -m "release: v2.2.0"
git tag v2.2.0
git push origin main --tags
```
